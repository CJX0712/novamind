# ADR-001: 协议 + 注入实现（离线兜底 / 生产可替换）

- **状态**：Accepted（2026-09-22）
- **作者**：晨星

## 背景

用户要求「搭建端到端可实际运行的完整 AI 系统」，并强调：优先复用开源成果、各模块单一职责、接口明确、可独立验证且能协同、可在干净环境一键复现、自主诊断修复依赖/编译/运行时错误。

核心矛盾：生产级 RAG 依赖大模型与向量库（网络/模型/算力），但「可复现、可验证、可 CI」要求系统在无网/无模型时仍能完整跑通。二者必须同时成立。

## 决策

采用 **Protocol 定义接口 + 双实现（离线兜底 / 生产）+ 容器按配置注入** 的架构：

- 每个 AI 模块在 `core/protocols.py` 用 `typing.Protocol` 定义契约。
- 每个模块提供至少两种实现：离线兜底（确定性、无依赖、无网络）与生产实现（Ollama / Qdrant / ONNX）。
- `core/container.py: build_system(settings)` 依据 `Settings`（环境变量 `NM_*`）选择实现并装配成 `System`。业务代码（retriever/agent/api）只依赖 Protocol，不依赖具体实现。

## 后果

- **正面**：
  - 离线兜底使 CI 与干净环境可一键复现（9 单测 + 6 E2E 全绿）。
  - 切换生产引擎为零代码改动（仅环境变量）。
  - 新后端实现只需在 `build_system` 注册一处，契约驱动、可独立单测。
- **负面 / 代价**：
  - 需维护双实现，代码量上升。
  - 离线兜底（HashEmbedder / MockLLM）仅是「可验证支点」，真实质量以生产后端为准，文档须明确区分。

## 关联决策

- ADR-002（计划）：生产重排采用 ONNX Runtime 而非在线 API，延续「零编译、本地优先」约束。
- 与 `docs/SPEC.md` 第 4 节技术架构、第 8 节模块接口互锁。

## 验证

- `tests/test_system.py` 中离线构建 `build_system(Settings(...))` 并通过检索/智能体/评测单测。
- `tools/verify.py` 在零外部依赖下全绿，证明离线链路可用。
